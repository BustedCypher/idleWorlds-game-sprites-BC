IdleWorlds  ·  Design Proposal

Modular
Server Events

A once-a-week world event that is never the same twice

One roll at server reset. Six days in seven, nothing happens and the day proceeds exactly as it does now. On the seventh, four modules are drawn from four separate pools, each at a randomly rolled magnitude, checked against each other for coherence, given a name derived from what was actually drawn, and published to the whole server.

This document specifies the eighty modules, the draw pipeline, the coherence gate, the naming system and the balance clamps — and hands over a verified reference implementation so none of it has to be guessed at.

1The shape of the system

Live-service events usually fail in one of two ways. Either they are hand-authored, which means there are twelve of them and players have seen all twelve by March; or they are pure random multipliers, which means every event is "×2 something" and none of them are memorable. This system is built to avoid both.

The core idea is that an event is not one effect. It is a Boon, a Twist, a Focus and a Flourish, drawn independently and then reconciled. The Boon is the gift, the Twist is the complication, the Focus is where it lands, and the Flourish is the server-wide topper. That structure is what makes a random draw read as a designed event: the grammar is fixed even though every word in the sentence is rolled.

Two consequences follow, and both are the point:

  • The combination carries the meaning, not the module. "More gold" is dull. "More gold, but one resource family has stopped dropping entirely, and only in the top five zones, while market tax is waived" is a day players talk about — and none of those four pieces had to be written for each other.
  • The name is derived, not authored. Nobody writes a name for an event that has never existed before. The system reads the tags off what it actually drew, works out what kind of day it is, and names it from a pool matching that kind. A player who sees COMBAT EVENT — Marked Reaver's Hour knows what the day is about before reading a word of the detail.
The design constraint this is built against
A player who logs in on an event day should be able to say, in one sentence, what is different — and should not be able to predict what next week's event will be. Everything below serves those two sentences.

What it costs to run

One integer roll per day, four table lookups, and a JSON blob published to a cache. There is no live tuning, no per-event content and no scheduling. Once the tables are in, the system generates events for years untouched, and the pools are additive: adding one new module to each of the four takes the structure count from 12,960,000 to over 15.7 million.

2The daily gate

At the turn of the server day — the same boundary the Daily XP Boost already uses — the server rolls once. A value below 1/7 makes the coming day an event day. Everything else about the day is unchanged, and on a non-event day the system does nothing at all: no banner, no flag, no payload.

Two guards sit either side of the raw roll, because a memoryless 1-in-7 is not actually the player experience anyone wants:

GuardThresholdWhy
Drought floor16 quiet days A pure 1-in-7 produces a six-week gap surprisingly often — a 44-day drought appeared within ten simulated years before this guard existed. Sixteen quiet days force an event on the seventeenth. This is the only reason the observed cadence is faster than one in seven.
Streak ceiling2 in a row Back-to-back event days are a pleasant surprise at 1-in-49. Three in a row reads as broken, and devalues the fourth. The third consecutive roll is suppressed.

A decision to make deliberately
The drought floor trades exactness for predictability: the cadence becomes 1-in-6.59 rather than 1-in-7. If the 1-in-7 figure is something you want to state publicly and have be literally true, lower the base rate to about 1-in-7.8 and let the floor bring it back — or drop the floor and accept that once a decade players will go six weeks without an event and conclude the system is broken. Our recommendation is to keep the floor and describe the cadence as "about once a week".

Why the gate gets its own sub-seed

The gate is rolled from seed + "|gate", not from the same stream that draws the modules. If both came off one stream, the modules drawn would be statistically conditioned on the gate having passed — a subtle and very annoying class of bug where certain modules quietly never appear. Separate sub-seeds cost nothing and remove the question entirely.

3The four slots

Each slot is its own pool of twenty modules. A module belongs to exactly one slot and cannot appear in another. That is a deliberate constraint rather than a limitation: it is what guarantees every event has one gift, one complication, one scope and one capstone, and it is also what prevents two modules that inflate the same number from ever landing together.

SlotRoleWhat it contributesRule it always obeys
ABoon The headline gift — the reason to log in today. Always framed as a straightforward positive. Never carries a downside.
BTwist The complication that changes how you play rather than how much you get. Most Twists trade something away for something better. Supplies the adjective in the event's name.
CFocus Where the event lands: a zone, a skill, a tier band, a four-hour window, or the whole world. Must be able to reach both the Boon and the Twist — see §6.
DFlourish The server-wide capstone that applies regardless of how a player spends the day. Always globally reachable, so nobody is locked out by build or level.
Why slot separation matters more than it looks
If all eighty modules sat in one pool and four were drawn from it, roughly one event in twenty would draw two modules that multiply the same quantity — and those are exactly the events that break an economy. Because Coin Flood (A1) and Silver Tongue (A13) are both Slot A, they can never co-occur. The structure does the balance work that would otherwise need a hand-maintained conflict matrix with 3,160 entries in it.

Slot D is the accessibility slot

It is worth being explicit about this, because it is easy to lose in implementation. Slots A, B and C can all end up narrow — one skill, one zone, one enemy family, four hours. If that were the whole event, a player whose evening does not intersect the Focus gets nothing at all and correctly concludes the event was not for them. Every Slot D module is globally reachable precisely so that never happens: whatever else the day is, the Flourish is for everyone.

4The draw pipeline

Ten steps, in order. Steps 1–2 decide whether there is an event at all; 3–6 decide what it is; 7–9 make it legal and safe; 10 publishes it.

Figure 1 — the draw pipeline. Blue is a random draw; green is a filter.

Determinism

The whole pipeline is a pure function of the server-day string and the recent event history. Given the same inputs, every shard, the client, the wiki and any third-party tool compute byte-identical results. That is what makes the event verifiable rather than something players have to take on trust — and it means a desync is a visible bug rather than a silent divergence.

5Magnitude and Rank

Each of the four drawn modules independently rolls a magnitude band, weighted 45 / 37 / 18 across I, II and III. This is the single most important multiplier on variety in the whole system: without it, there are 160,000 possible events and the first repeat is expected within about eight years of weekly events. With it, there are 12,960,000.

The bands are worth 1, 2 and 4 points. The sum across four modules is the event's intensity, from 4 to 16, which maps to a public Rank. Rank is what players actually talk about — it is the difference between "there's an event today" and "get online, it's a Grand".

RankIntensity TheoreticalMeasuredFrequency
Rank I · Faint4–517.6%24.3%about 13.5 a year
Rank II · Rising6–850.4%46.7%about 25.9 a year
Rank III · Greater9–1230.1%27.1%about 15.0 a year
Rank IV · Grand13–162.0%1.8%about 1.0 a year

Measured share differs from theoretical because Open World days (§6) damp every other module one band, which pulls a slice of the distribution downward. That is intentional: the widest events should also be the mildest.

Rank IV is deliberately about once a year
A Grand event is a genuine occasion — three of four modules at their top band. At 55 events a year and a 1.8% share, players will see roughly one a year, and it should get a distinct banner, a distinct colour and an announcement. If it fires twice in eighteen months that is normal variance, not a bug; resist the urge to hand-tune it after the first cluster.

Point weighting is not linear, on purpose

Band III is worth 4 rather than 3 because a Rank should reflect the presence of an extreme, not an average. Four modules at band II (intensity 8) is a solid Rising day. Two at band III and two at band I (intensity 10) is a lopsided day with two genuinely dramatic effects, and it should — and does — rank higher.

6The coherence gate

Independent draws produce nonsense on their own. Rich Veins (gathering yields) under a Warfront focus (combat only) is an event with no effect whatsoever — it would publish a banner, promise a bonus, and do nothing. This is the failure mode that makes procedural events feel broken, and it is not rare: without a gate, it happens on roughly a fifth of draws.

Surfaces

Every module declares which parts of the game it touches: COMBAT, GATHER, CRAFT, WORKORDER, VILLAGE, TRADE, or GLOBAL. GLOBAL intersects everything. Two modules overlap if either is GLOBAL or their surface sets intersect.

The rule

A Focus is legal for a given Boon and Twist if it overlaps both of them, and the pair is not in the hard-ban table. Rather than draw a Focus and test it, the system filters the Slot C pool first and draws from what survives. C12 Open World is GLOBAL, so the surviving pool is never empty and there is no fallback path to get wrong.

MeasureValueReading
Legal Focuses, mean8.9 of 20 a typical Boon/Twist pair admits about nine of the twenty Focus modules
Legal Focuses, range2 – 16 the low end is two narrow modules pulling in different directions; the high end is two GLOBAL modules
Open World days8.6% drawn naturally from the filtered pool, not used as a fallback

The hard-ban table

Surfaces catch the great majority of incoherence structurally. A short explicit list handles what they cannot — currently one entry, and it is the extension point for anything discovered in playtest:

PairReason
B10 × C13 Two competing time gates. Night Shift makes the event dormant for the first twelve hours; Hour of Power designates a four-hour window that may fall inside the dormant half. The intersection is either incoherent or empty, and players cannot be expected to reason about it.
Verified, not assumed
The gate was tested by asserting the exclusions it should make — Warfront is correctly refused a gathering Boon, Harvest is correctly refused a combat Twist, Open World is always legal — and then by disabling each rule in turn and confirming the assertions fail. A check that has never been observed failing is not a check.

7Naming: tags, themes, titles

Every module carries one primary tag and zero or more secondary tags from a fixed set of eleven. On an event day the system tallies them across all four drawn modules — primary scores 2, each secondary scores 1 — and the highest total is the event's Theme.

Tie-breaks, in order

  1. RISK never wins a tie. It rides along as a secondary tag on most Twists, so on a plain plurality it would take about a third of all themes and every event would be called a gamble. It is removed from any tied set — but it is allowed a clean plurality, which is what produces the genuinely rare gambler's day. Measured share: 4.7%, roughly two and a half a year.
  2. Slot A's primary tag wins if it is among the leaders. The Boon is the headline, so when the draw is ambiguous the gift decides what kind of day it was.
  3. Slot D's primary tag, then declaration order, as final deterministic backstops. These fire rarely but must exist — a tie-break that can return "no answer" is a crash on a live server at reset.

Composing the title

The name is adjective + noun. The adjective comes from the drawn Twist — four per Twist module, eighty in total — so the most distinctive mechanic of the day is what colours the name. The noun comes from the Theme pool, ten per theme. The format is:

<THEME> EVENT — <Adjective> <Noun>                      COMBAT EVENT — Marked Reaver's Hour
<THEME> EVENT — <Adjective> <Noun> Ascendant   (Rank IV)  VILLAGE EVENT — Patient Bonfire Night Ascendant
<THEME> EVENT — <Adjective> <Noun> <Numeral>   (a return) LOOT EVENT — Devil's Trove III

That is 8,800 distinct titles in the pool. A title used within the last 100 events is redrawn; beyond that window a repeat is permitted and numbered from the archive. This turns the one genuinely unavoidable collision into a feature — players remember the third Ravening Blood Moon, and a returning name reads as a sequel rather than a bug. Over 100 simulated years and 5539 events, 0 unnumbered duplicate names occurred.

8Anti-repeat memory

Raw combination count is not the same as felt variety. An event whose modules all appeared last week feels repetitive even if the exact four-tuple is new. Three cheap memories fix that; all three are small enough to keep in the same row as the event archive.

MemoryWindowEffect
Module cooldown4 events A module that has appeared in any of the last four events is removed from its pool. At about 55 events a year that is roughly a month's rest, and it is what stops the same Boon showing up three times in five weeks.
Title memory100 events A title used in the last 100 events is redrawn, up to eight attempts.
Signature memoryarchive The full A2-B10-C4-D1-style signature is stored per event. Used for the numeral suffix, for "this has happened before" in the archive UI, and as the source for D20 Echo of Days.
The cooldown slightly raises collision odds — knowingly
Blocking four modules per slot shrinks each pool from 20 to as few as 16, which raises the chance of an exact structural repeat by roughly 1.9×. Over 100 simulated years the system produced 8 exact structural repeats across 5539 events, against about 1.2 expected with no cooldown. That is the right trade: an exact repeat a century apart is invisible, while the same module twice in a fortnight is not.

9How many events are there really?

The brief asked for enough combinations that no two events are ever likely to be the same. Here is the honest accounting, with the weakest claim first.

CountingCountWhat it includes
Module identity only160,000 204. Not sufficient on its own — at 55 events a year, a repeat becomes more likely than not inside nine years.
Structure — modules + ranks12,960,000 204 × 34. This is the number to quote: it is what a player would perceive as "the same event".
With rolled targets56,800,501,560 Includes which zone, which skill, which enemy family, which window. Genuine variety, but dominated by C14's ordered four-skill rotation; we do not lead with this number.
Distinct names8,800 80 Twist adjectives × 110 Theme nouns, before the archive numeral.

When would a repeat actually happen?

Against the structural count of 12,960,000, and by the birthday bound, the expected number of events before a first exact structural repeat is about 4,512 — roughly 81 years of weekly events. Over a far more realistic ten-year horizon, the probability of any exact structural repeat occurring at all is 1.18%.

The 100-year simulation bears this out: 8 structural repeats in 5539 events, and even those differ in their rolled targets. In practice, no player will ever see the same event twice.

Where the variety actually comes from
Note which factor is load-bearing. Going from 20 modules per slot to 25 would multiply the structure count by 2.4×. Adding the magnitude roll multiplied it by 81×. If schedule pressure forces a cut, cut modules — never cut magnitude bands.

10Balance clamps

Slot separation prevents most stacking, but not all of it. Four clamps run after the draw and before publication.

ClampRule
Open World damping If C12 Open World is drawn, every other module drops one magnitude band (never below I). Removing all restriction has to cost something, or Open World becomes the strictly best Focus. C12's own band is pinned to I before intensity is summed — its three bands are identical text, so letting its roll into the sum scored the mildest days of the year as some of the strongest. Measured effect: Open World days average intensity 4.6 against 7.6 elsewhere, which is correct.
Risk floor A10 Second Wind at band III removes the death penalty entirely. Beside B11 Glass Cannon — the Twist whose whole point is that you might die — that neutralises the day's only real danger. When both are drawn, A10 is held to band I. This is the template for any future conditional clamp: reduce a magnitude, do not ban a pair.
Ceiling No single quantity may exceed ×4 from all event sources combined (×6 at Rank IV). Applied at the point of effect, after every multiplier is resolved. This is the backstop that means a new module can be added without re-deriving every interaction it might have.
Kill switch A single server flag suppresses the day's event and reverts to normal rules without a deploy. Non-negotiable for a system that generates content nobody reviewed in advance.
The clamp that will be needed and is not here yet
Nothing in this spec models the interaction between event multipliers and existing permanent player bonuses — gear Gold Find, Item Find, add-on buffs, set bonuses. A player at the top of the gear curve will get materially more out of Coin Flood than a new one, which is fine, and out of Fortune's Eye specifically, which may not be. Decide before launch whether event bonuses are additive with gear stats or multiplicative; the ×4 ceiling assumes additive.

17Reference implementation

The full engine accompanies this document as a single Python file with no dependencies: the eighty modules, the pipeline, the naming system, the clamps and the simulation harness that produced every number quoted here. It is intended as an executable specification — the tables in §11–§14 are generated from it, so they cannot drift.

The PRNG

Determinism across server, client and any third-party tool requires everyone to agree on the random stream, which means specifying the generator rather than using each platform's built-in. The system uses FNV-1a to hash the seed string to 32 bits and mulberry32 to expand it.

function fnv1a(s){ let h = 0x811C9DC5;
  for (const c of Buffer.from(s,'utf8')) { h ^= c; h = Math.imul(h, 0x01000193) >>> 0; }
  return h >>> 0; }

function mulberry32(a){ return function(){
  a = (a + 0x6D2B79F5) >>> 0;
  var t = a;
  t = Math.imul(t ^ t >>> 15, 1 | t);
  t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
  return ((t ^ t >>> 14) >>> 0) / 4294967296; }; }

// seeds
const gate  = mulberry32(fnv1a(serverDay + '|gate'));   // 1-in-7 check
const draw  = mulberry32(fnv1a(serverDay));             // module draws
The port is verified, not assumed
The Python reference and this JavaScript were run side by side over four seed strings — including a real server-day string and a gate sub-seed — and compared to twelve decimal places across six successive draws each. All 24 values match exactly. The subtlety worth knowing about: t + Math.imul(...) in JS is a float64 addition of two int32 values that is only truncated to 32 bits by the following ^. A port that masks to 32 bits too early diverges after a handful of draws, and the divergence is invisible until two clients disagree about what day it is.

Draw order is part of the contract

Because every draw consumes from one stream, the order of calls is load-bearing. A, then B, then the filtered C, then D; magnitude immediately after each module; rolled target immediately after magnitude. Reordering any of these produces a different but equally valid event, which means a refactor that looks purely cosmetic will silently change every future event and break agreement with any client that was not redeployed at the same instant. Freeze the order, and put a comment saying so next to it.

18The published event contract

The event must be published as machine-readable data at a same-origin endpoint. This is the single most important integration requirement in this document, and it is worth being blunt about why.

The lesson already paid for
The Daily XP Boost has no offline answer. Because it is not published anywhere machine-readable, external tools have to scrape a wiki page through third-party CORS readers, and when that fails the only correct behaviour is to display "unavailable" — because a wrong guess applies a bonus to skills that do not have one and withholds it from ones that do, and every XP-per-hour figure downstream inherits the error while still looking plausible.

A modular event system is strictly worse in this respect: there are four simultaneous effects instead of one, several are multiplicative, and no external tool can possibly infer them. If the event is not published as data, every calculator in the ecosystem is silently wrong for one day in seven. Publishing it is a few lines of JSON and it prevents that entirely.

Requirements

  • Same-origin, e.g. /api/daily-event. An absolute URL serving 200 with no Access-Control-Allow-Origin header is discarded by every browser and looks identical to "no event today".
  • Numbers, not prose. "goldMultiplier": 1.6, not "Gold is increased by 60%". Prose has to be parsed, and parsers break silently.
  • Absent is not zero. A multiplier that does not apply should be absent from the payload, never present as 0 or 1. The distinction between "no bonus" and "not applicable" matters to consumers.
  • Available on non-event days too, returning {"event": null}. Silence is ambiguous with failure.
{
  "serverDay": "2026-12-18",
  "event": {
    "id": "evt-2026-12-18",
    "name": "COMBAT EVENT — Marked Reaver's Hour",
    "theme": "COMBAT", "rank": 2, "rankName": "Rising", "intensity": 6,
    "signature": "A4II-B19I-C7I-D15II",

Every consumer — the in-game banner, the event archive, the wiki, and the community calculators — reads this one payload. Nothing re-derives the event from the seed in production, even though it could; the seed is for verification and for showing players why today is what it is, not for parallel implementations that can drift.

19Operations, testing, rollout

What to test

CheckAssertion
DeterminismThe same seed and history produce a byte-identical payload on every shard and in the client port. Assert against stored fixtures.
PRNG agreementServer and client agree to 12 decimal places over at least 6 draws from at least 4 seeds. This catches the int32 truncation bug described in §17.
Gate coherenceEvery Focus in a filtered pool overlaps both the Boon and the Twist, and every excluded one fails a rule. Then disable each rule and confirm the assertions fail.
Non-empty poolFor all 400 Boon × Twist pairs, the filtered Focus pool is non-empty. This is a finite exhaustive check — run it, do not reason about it.
Clamp ceilingOver a long simulated run, no resolved quantity exceeds ×4 (×6 at Rank IV).
DistributionOver 10,000 simulated events: every module and every theme appears, and rank shares are within tolerance of §5.

A check that returns an empty list on success only means something if you can tell "empty" from "did not run" — make the runner report how many assertions it executed, not just how many failed.

Telemetry worth having from day one

  • Focus pool size per event — the health metric for the gate. If the mean drifts below about 5, the tables have grown too narrow and events will feel samey.
  • Per-module appearance counts. Any module at zero after a simulated decade is unreachable and is a bug in its surfaces or tags.
  • Active players and session length on event days against the trailing non-event baseline, split by Rank — this tells you whether Rank is landing.
  • Which Boon/Twist pairs produce the smallest pools — the candidates for a new Focus module.

Suggested rollout

  1. Shadow mode. Run the roll daily, publish nothing, log everything, for two to four weeks. Check that the events that came up sound like days you would want to ship.
  2. Reduced pools. Launch with a subset — say twelve modules per slot — chosen for effects that already exist in the game and need no new systems. The structure count is still over 1.6 million.
  3. Widen. Append modules as their underlying features land. Because pools are additive and the gate is structural, that requires no other changes.
Player-facing communication
Publish the module list and the tag rules. The system is far more interesting to players who can see the machine — an archive page listing every past event with its signature, its rank and its numeral turns a random daily buff into something with history that players collect and compare. It also makes Echo of Days (D20) legible instead of confusing.

20Open questions for the developer

These are the decisions this document deliberately does not make, because they depend on the live game and on your intent rather than on the structure.

  1. Additive or multiplicative with gear? The single biggest balance question (§10). The ×4 ceiling assumes additive.
  2. Are the ten skills the right parameter pool? The skill list used here is illustrative and must be bound to real skill IDs. Likewise the 34 zones, 12 gear slots, 8 enemy families, 8 resource families and 8 damage types — several of these are inferred from the existing toolkit and need confirming against the live data model.
  3. Which modules need new systems? Roughly a dozen — the server pot (B12), the wandering merchant (B15), the temporary rift (D14), the event shop (D5), leaderboards (B13), the server goal (D7) — are meaningful engineering in their own right. They are worth keeping in the tables as targets, but the reduced-pool launch in §19 exists so they are not blockers.
  4. Does the death penalty exist in the form A10 assumes? Several Twists assume there is a cost to dying worth removing or raising. If there is not, B5, B11 and A10 need rewriting.
  5. Should events be per-shard or global? This spec assumes global, which is why the seed is the server-day string alone. Per-shard events need the shard ID in the seed and change the social character of the system considerably.
  6. What happens to an event in progress across a patch? If module effects are read live from config, a mid-day deploy changes the event under players. Freeze the payload at reset and read from the frozen copy.
What is already done
Eighty modules with effects, tags, surfaces and three magnitude bands each. The gate, the clamps, the naming system, the anti-repeat memories and the distribution tuning. A verified deterministic PRNG with a matching JS port. A 100-year simulation harness and the numbers it produces. What remains is binding the effects to real game systems and deciding the six questions above.
